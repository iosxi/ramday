# RamDay（伸び縮みする RAM ディスク）

使った分だけメモリを確保し、ファイルを消せば自動でメモリを返す RAM ディスク。
起動中は Windows の TEMP / TMP 環境変数を RAM ディスクに切り替え、解放するときに元へ戻す。

- **インストール不要**。`RamDay.exe` 1 個で動く（ドライバも exe に埋め込んである）。
  Windows の起動時に自動で始めたいときは `RamDayLaunch.exe` も置く
- **レジストリに残さない**。ドライバの登録は起動中だけで、TEMP の元の値は exe の隣の
  `RamDay.ini` に控える（詳しくは「レジストリについて」）
- 最小容量は 0 バイト。書き込んだ分だけメモリを使い、上限は起動時に指定した最大容量

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `RamDay.exe` | **これ 1 個で動く**。依存は Windows 標準の DLL だけ |
| `RamDayLaunch.exe` | 前回「開始」した設定で RamDay を開始して、すぐ終わる（スタートアップ登録用） |
| `ramdaylaunch.c` / `.rc` / `.manifest` | `RamDayLaunch.exe` のソース・リソース・マニフェスト |
| `ramday.c` | 本体のソース |
| `ramday.rc` / `resource.h` | ダイアログ・アイコン・バージョン情報・埋め込みドライバのリソース |
| `ramday.manifest` | 見た目（コモンコントロール v6）と高 DPI 対応の宣言。権限は一般（`asInvoker`） |
| `ramday.ico` / `make-icon.py` | アイコンと、その生成スクリプト |
| `imdisk/imdisk.sys` | ImDisk Virtual Disk Driver 2.1.2.66（x64、Microsoft 署名済み、**無改変**） |
| `imdisk/LICENSE-ImDisk.txt` | ImDisk のライセンス（GPL v2） |
| `build.cmd` | ビルド手順（MinGW-w64 の gcc / windres） |

実行すると exe の隣に `RamDay.ini`（設定と TEMP の控え）、`RamDay.log`（動作記録）、
`imdisk.sys`（埋め込みドライバの書き出し先）ができる。exe の場所に書き込めないときは
ドライバだけ `C:\Windows\Temp\RamDay-imdisk.sys` に書き出す。

## 使い方

`RamDay.exe` をダブルクリックすると**設定画面**が開く（管理者権限は要らない）。
設定画面はいつでも開ける。RAM ディスクが動いている間も、閉じたあとも。

1. 設定画面で次を選んで「**開始**」を押す（ここで管理者権限の確認が出る）
   - **ドライブ文字**（空いている文字だけが並ぶ。既定は R:）
   - **最大容量**（数値と MB / GB。16 MB 以上、実メモリ以下）
   - **ファイルシステム**（NTFS / exFAT / FAT32。FAT32 は 32 GB まで）
   - **TEMP と TMP を RAM ディスクへ一時的に切り替える**（切り替え先は既定で `R:\Temp`。
     ユーザー側・システム側をそれぞれ選べる。今の値もここに表示される）
2. RAM ディスクを管理する**ワーカー**（同じ exe を管理者として起動したもの）がタスクトレイに
   常駐し、作成した旨の通知が出る。設定画面の「状態」欄に、ドライブ・メモリ使用量が出る。
3. **設定画面は閉じてよい**。RAM ディスクはワーカーが持っているので動き続ける。
4. やめるときは設定画面の「**終了**」（またはトレイの「解放して終了」）。
   TEMP / TMP を元の値に戻し、RAM ディスクを外してメモリを返す。

動いている間の設定画面は、動いている RAM ディスクの設定を表示し、入力欄は変えられない
（変えるには一度「終了」する）。止まっているときは、前回「開始」した設定が初期値になる
（`RamDay.ini` に残る）。

トレイのアイコン（ワーカー）:

- **ダブルクリック** — 設定画面を開く
- **右クリック** — 設定画面を開く、今のメモリ使用量（クリックで詳しい状態）、ドライブを開く、解放して終了
- **マウスを乗せる** — メモリ使用量と最大容量

RAM ディスク上のファイルを開いたままのプログラムがあると、終了のときに
「強制的に終了しますか？」と訊く。強制すると、そのファイルの保存していない内容は失われる。

## Windows の起動時に自動で開始する（RamDayLaunch.exe）

`RamDayLaunch.exe` を `RamDay.exe` と**同じフォルダー**に置き、スタートアップに登録する。

1. `Win + R` で `shell:startup` を開く（スタートアップフォルダーが開く）
2. そこに `RamDayLaunch.exe` のショートカットを作る

ログオンすると、`RamDayLaunch.exe` が `RamDay.exe -start` を起動してすぐ終わり、
`RamDay.exe` が**前回「開始」した設定**（`RamDay.ini`）でワーカーを起動する。

- すでに RamDay が動いていれば何もしない。
- まだ一度も「開始」していなければ、設定画面を開く。
- 開始できなかったとき（ドライブ文字が使われていた、など）は理由をメッセージで出す。
- ドライバの読み込みに管理者権限が要るので、UAC の確認が出る設定の PC では、ログオンのたびに
  確認が 1 回出る（「確認せずに昇格する」設定なら出ない）。タスクスケジューラに
  「最上位の特権で実行」で登録すれば確認なしにできるが、Windows 側に登録が残るので RamDay は使わない。
- `RamDayLaunch.exe` 自身は管理者を求めない（管理者を求める exe はスタートアップから起動されないため）。

## コマンドライン

引数を付けると設定画面を出さずにすぐ開始する（ワーカーを起動する。管理者でなければ
権限の確認が出る）。ショートカットやタスクスケジューラ向け。

```
RamDay.exe -d R -s 4G -fs NTFS                 R: に最大 4 GB の NTFS。TEMP は R:\Temp へ
RamDay.exe -d R -s 512M -fs exFAT -notemp      TEMP は切り替えない
RamDay.exe -d T -s 8G -temp T:\tmp -scope user ユーザー側の TEMP / TMP だけ T:\tmp へ
RamDay.exe -start                              前回「開始」した設定で開始する（RamDayLaunch.exe と同じ）
RamDay.exe -release                            動いている RamDay を解放して終了させる（管理者不要）
RamDay.exe -release -force                     使用中のファイルがあっても強制的に解放
RamDay.exe -restore                            前回の異常終了の後始末だけ行う（管理者の確認が出る）
```

`-` の代わりに `/` でもよい。`-quiet` を付けるとメッセージボックスを出さず、
エラーは `RamDay.log` にだけ書く。

`-release` の終了コード: 0 = 解放した、2 = RamDay が動いていない、
3 = 応答がない、4 = 使用中のファイルがあるので取りやめた（`-force` で強制できる）。

## 仕組み

### 2 つのプロセス

| | 設定画面 | ワーカー |
| --- | --- | --- |
| 起動 | `RamDay.exe`（引数なし） | 設定画面の「開始」が `RamDay.exe -worker ...` を管理者として起動 |
| 権限 | 一般 | 管理者（ドライバの読み込み、システム側 TEMP の書き換え） |
| 役割 | 設定の入力、状態の表示、開始・終了の依頼 | RAM ディスクの作成・読み書き・解放、TEMP の切り替え、トレイ |
| 終わると | RAM ディスクはそのまま | RAM ディスクを外して終わる |

- ワーカーは状態（動作中か、ドライブ、容量、メモリ使用量、TEMP）を共有メモリ
  `Local\RamDay_Status` に 0.5 秒ごとに書き、設定画面はそれを読んで表示する
  （一般権限からも読めるよう、認証済みユーザーに読み取りを許している）。
- 「終了」は設定画面がワーカーのウィンドウに解放を依頼する。ワーカーは一般権限からの
  この依頼だけを受け付けるよう許可している（`ChangeWindowMessageFilterEx`）。
- 開始に失敗したときは、ワーカーが理由を `RamDay.ini` の `[Status] LastError` に書いて終わり、
  設定画面がそれを表示する。
- ワーカーは同時に 1 つだけ。終了直後に「開始」しても、前のワーカーの後始末を最大 10 秒待つ。

### RAM ディスク

```
アプリ ──▶ NTFS など ──▶ imdisk.sys（\Device\ImDiskN）
                              │ 共有メモリ + イベントで要求を転送
                              ▼
                         RamDay.exe のプロキシスレッド
                              │
                              ▼
                     64KB ブロックの表（書いた所だけメモリを確保）
```

- ディスク本体は ImDisk の「プロキシ」型デバイス。読み書きの要求が共有メモリ経由で
  RamDay に届き、RamDay が自分のメモリで応える。
- 中身はディスク全体ぶんのアドレス空間を予約しておき、**書かれた 64KB ブロックだけ**
  コミットする。読んだ所が未確保なら 0 を返す。
- 確保したメモリは作業セットのハード下限に含め、ページファイルへ追い出させない
  （`VirtualLock` で先に割り当てる方法は、実測で書き込みが半分の速さになったので使っていない）。
- 要らなくなったブロックは 2 つの道筋で返す。
  - **TRIM / ZERO**: ファイルシステムが送る TRIM、ドライバが 0 書き込みを置き換えた ZERO 要求
  - **回収**: 2 秒ごとに、確保量がファイルシステムの使用量より多ければ空きビットマップ
    （`FSCTL_GET_VOLUME_BITMAP`）を読み、全クラスタが空きのブロックを返す。
    走査の直前に世代番号を進め、それ以降に書かれたブロックは返さないので、
    走査中の書き込みとは競合しない。FAT 系のデータ領域の位置は
    `FSCTL_GET_RETRIEVAL_POINTER_BASE` で求める。

## 実測（2026-10-02、Windows 11 25H2・RAM 64 GB）

設定画面からの操作（v2 で確認）: 動作中に開いた設定画面がワーカーの状態を表示し、
「終了」→ 解放まで 0.4〜2.1 秒、続けて「開始」→ 動作中まで 0.7 秒。


非バッファ I/O、1 GB のファイル。C: は比較用の NVMe SSD。

| | 順次書き込み（新規） | 順次上書き | 順次読み込み | 4K ランダム読み | 4K ランダム書き |
| --- | --- | --- | --- | --- | --- |
| RamDay（NTFS） | 1,125〜1,255 MB/s | 2,479〜2,624 MB/s | 3,000〜3,145 MB/s | 59,800〜63,300 IOPS | 57,600〜60,800 IOPS |
| C:（SSD） | 1,418 MB/s | 2,008 MB/s | 1,936 MB/s | 10,315 IOPS | 44,315 IOPS |

- 新規の書き込みは、メモリのページを新しく割り当てる分だけ上書きより遅い。
- メモリの返却: 1 GB のファイルを消すと、NTFS・exFAT・FAT32 とも 1〜2 秒で確保量が元に戻った
  （例: 1,039 MB → 12 MB）。
- 作成から TEMP の切り替えまで約 0.2 秒、解放は約 1 秒。
- 回収を挟んで書いては消すを繰り返した後も、残したファイルの中身は変わらなかった
  （キャッシュを通さない読み込みのハッシュで確認。NTFS・exFAT・FAT32）。

## レジストリについて

RamDay が書き換えるのは次の 2 つだけで、どちらも解放時（異常終了なら次回起動時）に戻る。

1. **ImDisk ドライバのサービス登録**（`HKLM\SYSTEM\CurrentControlSet\Services\ImDisk`）
   - ImDisk がインストールされていなければ、起動時に登録してドライバを読み込み、
     **すぐに削除予約**にする。解放時にドライバを止めた時点で Windows が登録を消す。
   - 解放時、ディスクを誰かがまだ参照していると（強制解放したときなど）ドライバを
     止めずに読み込んだままにする。登録は削除予約済みなので、**次の再起動で Windows が消す**。
     次に RamDay を起動したときは、読み込まれたままのドライバをそのまま使う。
   - ImDisk がもともとインストールされていれば、それを使い、登録には触らない。
2. **TEMP / TMP 環境変数**（`HKCU\Environment`、
   `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`）
   - 書き換える前に元の値（`%USERPROFILE%\...` のような展開前の形と、値の型）を
     `RamDay.ini` の `[Backup]` に控え、解放時に書き戻す。

ほかに、エクスプローラーがドライブ文字ごとに作る
`HKCU\...\Explorer\MountPoints2\<文字>` を解放時に消す。

## 異常終了したとき

RamDay が強制終了されたり、電源が落ちたりして TEMP が RAM ディスクを指したまま残っても、
次に `RamDay.exe` を起動すると最初に `RamDay.ini` の控えから元へ戻す
（`RamDay.exe -restore` でも同じ後始末だけを行える）。Windows のサインアウト・
シャットダウンでは、終了処理の中で元へ戻す。

RamDay が強制終了されたときの RAM ディスクは、中身がもう無いのでそのまま取り外す。
このとき Windows 側にディスクへの参照が残り、**ドライバは次の再起動まで読み込まれた
ままになる**（サービス登録は削除予約済みなので、再起動で消える）。次に RamDay を
起動するのには差し支えない（読み込まれたままのドライバを使う）。

## 注意

- 管理者権限が要る（ドライバの読み込みと、システム側 TEMP の書き換えのため）。
- TEMP の切り替えは、切り替え後に起動したプログラムから効く。すでに動いている
  プログラムやサービスは、再起動するまで元の TEMP を使い続ける。
- RAM ディスクの中身は解放すると消える。残したいファイルは置かない。
- 最大容量は実メモリ以下にしか設定できない。実際に使うメモリは書き込んだ量
  （ファイルシステムの管理領域を含む）だけ。

MinGW-w64（gcc と windres）が PATH にある状態で `build.cmd` を実行する。
